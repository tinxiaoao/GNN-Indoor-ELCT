# Data and checkpoints

The public dataset contains automatically extracted room attributes, topology
tables and ELCT graphs from CubiCasa5K. `output/roomself_excel/`,
`output/topology_excel/` and `output/topology/` retain the full available
extraction outputs with their original filenames and directory structure.
See [source attribution and CC BY-NC 4.0 terms](../third_party/README.md).

The bundled `examples/synthetic_two_rooms/` maps are generated by
`scripts/make_synthetic_example.py` for interface examples and regression tests.
They are synthetic inputs, separate from the CubiCasa5K extraction dataset.

Semantic maps for 193, 11184 and 7795 are annotation-derived CubiCasa5K assets.
`configs/building_A/B/C.json` records their source type, hashes and dimensions.
`python -m geo_elct prepare-examples` copies the nine hash-bound maps and
backgrounds from a locally authorized processed dataset. The prepared extraction
mode defaults to `none`; select `--mode correction_v2` explicitly when desired.
Raw floor-plan images, SVG files, LMDB and training caches are obtained from
their upstream sources; `output/` contains the extracted results.

The GNN interface uses external VecFloorSeg source at commit
`c3f51b39a4649c6b978898589a71df2e9c8159ba`. Source preparation, dependencies,
upstream checkpoints and semantic-map handoff are described in
[GNN provenance](gnn_provenance.md). Use the upstream source and checkpoints
under their applicable terms.

The topology programs use explicit input manifests, including
`experiments/part_b_inputs.json`, and perturbation settings in
`experiments/part_b_protocol.json`. The [topology guide](part_b.md) describes
input preparation, generation and evaluation.

The MWM module is distributed as calculation code and methods. The user supplies
source geometry, transmitter and receiver coordinates, existing WI exports and
corresponding room references according to
[the external input format](../benchmarks/mwm/input_schema.md). Simulation
inputs and numerical comparison datasets are not included in this code release.
The Python workflow consumes existing exports offline; producing new exports
requires a valid Wireless InSite license.

Public provenance paths are project-relative. Keep local input bundles,
credentials and newly computed runs outside the published repository.
